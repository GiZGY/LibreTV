# OpenStream 全面性能与质量优化记录

## 范围

本轮覆盖 OpenStream 网站、Vercel Serverless API、Node 运行时和 LA TVBox bridge。目标不是单纯缩短测速数字，而是在不降低结果正确性、源可用性和代理安全性的前提下，让首屏、搜索、筛选和播放更快地给出可用内容。

生产部署不包含在本轮执行范围内。所有数据均来自生产基线或本地生产构建验证，合并后仍需通过 Vercel Preview 再做一次生产等价验收。

## 性能基线与结果

Lighthouse 使用同一版本 Chrome 和默认移动/桌面模拟参数。基线采自优化前生产站；优化后使用真实 HttpOnly 登录会话访问本地生产构建，并实际加载豆瓣推荐与封面，表格记录最终发布候选的认证冷启动。两组网络 RTT 不完全等价，传输量也因最终测试包含 16 张第三方封面而不能直接横比；主线程、布局稳定性和资源工程指标可用于回归判断。

| 指标 | 移动端基线 | 移动端优化后 | 桌面端基线 | 桌面端优化后 |
| --- | ---: | ---: | ---: | ---: |
| Performance | 98 | 99 | 98 | 100 |
| FCP | 1390 ms | 813 ms | 699 ms | 262 ms |
| LCP | 2002 ms | 2120 ms | 779 ms | 532 ms |
| Speed Index | 3202 ms | 833 ms | 1358 ms | 262 ms |
| TBT | 0 ms | 0 ms | 0 ms | 0 ms |
| CLS | 0.0476 | 0 | 0.0025 | 0 |
| 请求数 | 34 | 25 | 34 | 25 |
| 首屏传输 | 123.6 KB | 474.9 KB（含封面） | 123.6 KB | 475.1 KB（含封面） |

优化期间用认证态回归检测发现过一次 `CLS 1.034`：首次访问尚未写入默认设置时，豆瓣区域会在 3 毫秒内被隐藏后重新显示，导致页脚两次跨越首屏。现在豆瓣开关在持久化前后使用同一默认语义，认证完成只触发一次渲染，并为标签栏和推荐卡保留最终几何尺寸；修复后移动和桌面 CLS 均为 `0`。移动端只让首张豆瓣封面使用高优先级同步解码，其余封面保持低优先级懒加载，冷启动 LCP 稳定在约 `2.1 s`，剩余波动来自第三方豆瓣接口和海报 CDN。认证状态请求也在 deferred 主包前启动并由正式认证流程复用。对应断言已进入 `smoke:static-performance`。

构建预算：

- 首页 JS：49.3 KB Brotli。
- 首页 CSS：9.6 KB Brotli。
- 播放页主 JS：29.3 KB Brotli。
- 播放页线路切换模块：5.0 KB Brotli，按需加载。
- 质量检测运行时：3.7 KB Brotli，空闲抽样或手动检测时才加载。
- 首页和播放页均只有一个合并 CSS；首页只有一个业务 JS。

## 关键改造

### 首屏和静态资源

- 移除浏览器内 Tailwind 编译，统一在构建期生成 CSS。
- 使用 esbuild 合并、压缩并写入内容哈希版本。
- 按页面拆分首页、播放页、基础页和跳转页资源。
- 播放页线路切换代码改为用户打开时才加载。
- 播放分片探针和质量候选算法拆为独立运行时，不占用首页首屏下载。
- Vercel 对编译资源和本地图片使用一年 immutable 缓存。
- Node 服务启用 gzip 协商压缩并保留相同缓存语义。
- `/watch` 去掉固定 2.8 秒等待，立即执行安全跳转。

### 流式搜索

- 快源、慢源不再按层级串行等待；统一进入有优先级的并发池。
- 初始跨源并发为 4；当首批源持续占满时按 350 毫秒对冲扩展，硬上限为 7，避免前四个慢源阻塞后续快源。
- 第一批结果到达即渲染，后续源增量合并，不等待全部坏源。
- 相同请求去重，搜索结果按稳定键增量更新，DOM 写入合并到动画帧。
- 源成功率、失败、超时、最近耗时和质量分参与后续排序。
- HTTP 失败、网络异常、无效 JSON 与真实空结果使用不同状态；`unsupported/unplayable/dead` 在冷却期后只以最低优先级自动复检。
- 连续超时和连续快速错误都会进入 `dead` 冷却；瞬时详情/播放错误不会被误封为永久不可播放。
- 旧搜索链接和标准 CMS 搜索/详情接口保持兼容。

### 豆瓣推荐与筛选

- 推荐和筛选状态彻底隔离，刷新可恢复筛选模式。
- 筛选改用豆瓣批量接口，不再逐卡片请求 `subject_abstract`。
- 首屏先显示当前页，再在后台按窗口预取下一页。
- 页面 DOM 和请求结果分别缓存，返回上一页不重新构建卡片。
- 重复请求会取消旧任务，并用筛选快照隔离排队任务，避免快速切换年份、题材或翻页时发生竞态覆盖。
- 首次认证只发起一次推荐请求；静态骨架、标签栏占位和真实卡片尺寸一致，异步数据不再推动整页布局。

### 播放器

- 详情、集数标准化与播放源切换拆成独立模块。
- CMS 与 TVBox 源统一为标准集数结构。
- 支持播放故障检测、备用源切换、当前集和进度恢复。
- WebKit 换集重建播放器时会清理手势、进度和全屏监听，避免重复触发和长时间播放后的内存增长。
- 非 WebKit 原地换线也会解除旧 HLS `playing/timeupdate` 监听；移动端关闭 ArtPlayer 内置 3 倍长按，只保留统一的 2 倍交互。
- 详情请求取消信号会贯穿前端拦截器和上游代理请求，连续点击不同结果不会留下后台详情请求。
- 极速资源包装页在进入播放器和质量检测前统一规范成真实 M3U8 地址。
- HLS 代理继续流式转发、支持 Range，并保持主从清单和密钥/分片签名。

### 无感源质量系统

- 搜索成功不再等同于可播放。
- 质量链路依次验证：关键词搜索、详情、集数、真实播放清单、首个媒体分片。
- HLS 主清单可递归到媒体清单，首分片只取 4 KB Range 样本，避免完整下载。
- HTML、JSON、图片、短错误文本、空响应、错误内容类型和无分片清单都会判定失败。
- MPEG-TS 必须同时命中连续 188 字节同步位；`Gateway timeout` 等以 `G` 开头的短错误体不能伪装成分片。
- AES-128 HLS 会获取密钥并对 Range 密文做局部解密后再验证媒体签名；无法确认的加密方式保持未知态，不会误封源。
- 只有媒体探针或真实播放成功才能解除 `unplayable`，普通搜索成功不会错误洗白播放故障。
- 手动全源检测使用动态并发池，不被固定批次中的单个慢源拖住。
- 本地真实全源检测约 17 秒完成，并选出 5 个同时通过清单与首分片验证的源。
- 日常访问只在空闲期、非省流网络且没有搜索任务时低频抽样，结果写入本地源健康快照；不会在首屏自动压测全部源。

### Vercel 与安全代理

- Vercel 构建只发布 22 个白名单静态文件，不暴露源码、服务端文件或依赖清单。
- 认证、通用代理和 TVBox 转发分别打包为 3 个 `nodejs22.x` Serverless Function。
- 登录改为 HttpOnly 签名会话，不在 HTML、localStorage 或浏览器日志保存密码/hash。
- 配置导入只接受显式白名单键，自定义豆瓣标签只通过 DOM `textContent` 渲染，拒绝持久化脚本注入。
- 配置导入会先完成结构校验，再事务式写入；任一存储写入失败会恢复导入前状态。
- 低于 16 位的 `PASSWORD` 会同时禁用登录、session、普通代理和媒体资源令牌，不存在“登录拒绝但旧弱令牌仍可用”的分叉。
- 普通代理令牌短时有效；HLS 子资源使用绑定目标 URL 的资源令牌。
- 代理拒绝公网请求访问 loopback、link-local、RFC1918 和解析到内网的主机。
- 每次重定向重新校验目标，响应头使用白名单，流读取具备真实中止超时。
- bridge adapter 的每次重定向也重新做公网 DNS 校验；跨域跳转剥离授权与 Cookie，拒绝路径会主动释放响应体。
- 鉴权失败、敏感状态和错误响应均 `no-store`。
- 生产 CORS 默认关闭；只有显式设置 `CORS_ORIGIN` 才启用。
- 删除会自动写入 `main` 的上游同步与旧版本工作流；剩余 GitHub Actions 均为只读权限并固定到完整 commit SHA。

### TVBox bridge

- Vercel 只保留服务端 bridge 转发，URL 和 token 不进入浏览器。
- 携带 bridge token 时强制使用 HTTPS；认证请求遇到跨 origin 重定向会立即拒绝，不转发长期 bearer。
- bridge 支持请求合并、TTL/LRU 缓存、共享任务与单个客户端取消隔离。
- fetch 超时覆盖响应头和响应体解析，不会留下后台悬挂请求。
- `ready`、`timeout`、`unsupported`、`login_required`、`no_result` 明确区分。
- 荐片、瓜子、立播使用可执行 HTTP adapter；需要登录的网盘源不接入。
- 生产缺少 `TVBOX_BRIDGE_TOKEN` 时 fail closed。
- Docker 镜像使用非 root 用户并自带鉴权健康检查。

## 质量门

根项目：

```bash
npm run quality
```

覆盖构建、流式搜索、播放器回退、集数规范化、线路懒加载、质量选择、真实媒体探针、会话鉴权、TVBox 代理、通用代理、fetch 拦截、GitHub Actions 供应链约束、跳转页、bridge 缓存和静态资源预算。

bridge：

```bash
npm --prefix bridge/tvbox-bridge audit --audit-level=high
npm --prefix bridge/tvbox-bridge run smoke:ci
docker build --tag openstream-tvbox-bridge:quality bridge/tvbox-bridge
```

部署产物验证：

- `npx vercel build --yes`：通过，3 个函数均为 `nodejs22.x`。
- Vercel 静态产物约 1.3 MB，仅包含 22 个白名单文件；凭据与源码扫描为零命中。
- OpenStream 与 TVBox bridge 的 Node 22 Docker 镜像均构建成功。
- 两个容器均以 UID 1000 运行；网站真实 GET 返回 gzip，bridge 未授权健康检查返回 401。

浏览器验收覆盖：

- 未登录首屏不发起受保护 API 请求。
- 登录后豆瓣推荐图片正常。
- 筛选条件刷新恢复、分页预取和返回页缓存正常。
- 搜索结果流式出现且没有重复源请求。
- 极速资源详情、36 集解析和约 45 分钟真实 HLS 播放正常。
- 播放页线路模块仅在用户打开时加载。
- 390 × 844 移动端和 1920 × 1080 电视端无横向溢出。
- 最终发布候选 Lighthouse 移动端：Performance 99、Accessibility 100、Best Practices 100、FCP 813 毫秒、LCP 2.120 秒、Speed Index 833 毫秒、TBT 0、CLS 0。
- 最终发布候选 Lighthouse 桌面端：Performance 100、Accessibility 100、Best Practices 100、FCP 262 毫秒、LCP 532 毫秒、Speed Index 262 毫秒、TBT 0、CLS 0。

根项目与 bridge 的 `npm audit --audit-level=high` 均为 0 个漏洞。

## 已知边界

- `robots.txt` 仍显式禁止索引，这是产品原有隐私/版权策略，不作为性能缺陷修改。
- TVBox 上依赖 CatVod/JAR 或网盘登录的源仍不适合直接搬到无状态 Vercel。
- 浏览器本地健康快照只能代表该用户近期网络；跨用户全局健康度需要独立监控服务。
- 第三方源和 CDN 可随时变化，因此质量结果有有效期，不能成为永久白名单。

## 上线与回滚

上线顺序：

1. 合并后先观察 Vercel Preview 的构建和质量门。
2. 在 Preview 重跑首页、搜索、详情、播放和移动端关键路径。
3. LA bridge 使用新镜像滚动替换并先验证 `/api/tvbox/health`。
4. 最后再切生产流量。

回滚方式：

- 网站异常：回滚本次提交即可恢复旧 HTML/JS/API。
- bridge 异常：保留上一镜像标签，切回旧容器；网站 CMS 源不依赖 bridge。
- 源质量误判：可单独回滚 `js/playback-quality.js`、`js/quality-selection.js` 和 `js/app.js` 的质量探针调用，不影响搜索流式管线。
