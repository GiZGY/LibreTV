## 可重复运行

```sh
npm run audit:source-ads -- --out /tmp/ad-report.json
npm run audit:source-ads -- --sources bfzy,zy360,mdzy,tvbox:荐片 --out /tmp/ad-subset.json
npm run smoke:ad-guard
```

报告路径必须尚不存在。需要人工复核媒体时，可增加 `--evidence-dir /tmp/ad-evidence-new`；
目录必须新建且位于仓库外，权限 0700，文件 0600。媒体清单可能含签名地址，
原始证据只用于本机临时调查，不能提交；公开报告仅保留哈希、时间区间和状态。
默认命令只分析清单，不下载分片、不生成或启用新规则。

并发最多 3 个源；单次网络请求含读体 12 秒，bridge 每片名总超时 25 秒；
响应体最多 4 MiB、主清单嵌套最多 4 层。复用既有 HTTP 安全实现，拒绝内网地址及危险重定向。

## 覆盖边界

- 这是有边界的多源抽样，不是各源全片库或所有广告的验收。
- 不同转码、签名动态内容、新广告和不同分片边界仍可能未命中。
- 没有重复块不排除画面内水印、片头或只出现一次的插播广告。
- 原生 iPhone Safari 尚未真机验收。
- 回退时移除新增 02/03 规则即可；不要恢复删除 DISCONTINUITY 的旧算法。

## 尚未完成的产品能力

源能搜索、清单能下载、正片能播放、广告被完整识别是不同验收层级。
本次只有有限影片和明确素材的证据，不能推导出剩余源全部影片都无广告。
持续覆盖需要后台跨影片采样、重复内容聚类、视听证据核验、版本化规则更新和
播放边界回归。未知内容不能直接获得跳过权限，也不能通过一次清单分析宣称没有广告。
后续已在本地实现独立采样 worker、跨影片指纹队列、内容审核、过期/撤销、
规则导出及播放器匹配回归，见 [worker 说明](../services/ad-observer/README.md)
及 [验收记录](ad-observer-validation-2026-09-06.md)。尚未部署持续任务；
新素材的视听语义审核仍需要核验，规则也仍需正常验收后发布，不能宣称全自动广告全覆盖。
