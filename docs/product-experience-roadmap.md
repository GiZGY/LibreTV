# OpenStream 产品体验与防回归计划

更新日期：2026-11-06

**当前版本与发布门槛：** 正式站为 PR #46（`8068211`）。下文的设置简化、弹层统一、倍速拖动与首页轮播属于下一批本地候选。先验收本地操作，明确确认后才统一部署；候选不自动推送、合并或触发托管部署。无账号、无登录、七天验证会话和既有播放功能保持不变。

目标：打开后便于继续观看，播放中便于处理问题，异常后能够可靠恢复。全部条目纳入实施范围；产品不提供账号注册或登录。跨设备同步由使用者选择启用，以明确的设备配对授权建立关联。

状态约定：功能清单记录施工与对应回归的覆盖；每次候选的托管检查、预览和正式验收分别登记。已完成的历史勾选不代表后续变更自动验收通过；PR 检查通过也不覆盖 main 复跑失败。不适用与未运行的项目单列，不计为通过。当前候选见“本地验收入口”及第五至七节。

## 本地验收入口

- 当前门槛：产品方亲自验收并明确确认。此前不推送本批候选，不合并到 main，不触发正式部署。

## 二、防回归地基：先做再扩展

### G01 — 真实媒体自动回归与状态约束

- [x] 明确播放会话、媒体实例、持久化偏好和临时操作的责任边界；沿用现有模块，渐进整理，不为此重写前端框架。
- [x] 将倍速恢复与一次性的进度恢复分离；媒体重载、错误恢复、重新播放均执行一致性检查。
- [x] 取消已失效的请求，隔离旧实例事件；旧集的回调不修改新集的倍速、进度、线路或历史记录。
- [x] 建立本地可重复生成的 MP4/HLS 测试媒体；浏览器测试不依赖公网片源，运行时静音。
- [x] 将真实浏览器媒体回归接入 CI，不以源码片段、模拟视频或静态断言替代；每次执行结论单列。PR #43 的 PR 运行通过、main 复跑失败分别保留；PR #44 的 PR 与 main 已重新实际通过，后续候选仍独立执行。
- [x] 自动回归覆盖 Chromium 与 WebKit 引擎，本机另有独立 Chrome 样本；这些引擎结果不等同于 Safari/iOS 或独立 Edge 的实际浏览器验收。设备与模式结论在第七节单列。
- [x] 覆盖手动下一集、自然结束连播、跳片尾切集、手动换线、自动换线、HLS 错误恢复、媒体重载、拖动进度、后台恢复及长按临时加速。
- [x] 增加连续多次切集、快速重复操作、取消后重试和旧请求延迟返回的组合测试。
- [x] 校验实际媒体时间相对真实时间的增速；正常采样窗口不少于 10 秒，同时记录缓冲、拖动、暂停等干扰，异常窗口单独判定，不伪装为倍速通过。
- [x] 为新发现的缺陷增加先失败、修复后通过的测试；新代码、播放器库和依赖升级继续执行相应历史回归。

### G02 — 体验指标

- [x] 建立点击播放到首帧的耗时基线，分别识别验证、找源、地址解析和媒体加载阶段。
- [x] 定义卡顿占比、切集成功率、恢复成功率和用户主动换线次数。
- [x] 建立正确剧集、实际进度与倍速继承的成功判据；静音和各类全屏状态另作断言。诊断`outcome=success`本身不代表所有浏览器的原生全屏均通过；HTTP 200、容器健康或标签也不能单独作为播放证据。
- [x] 固定外部首帧与十秒实速口径，记录 PR #42 基线及 PR #44 同路径样本，并设定本路径复查触发值；不据小样本宣布普遍提速。
- [x] 指标采集遵循最小化原则，不采集 Cookie、Token、签名媒体地址或完整观看记录。

### G03 — 问题诊断

- [x] 增加主动触发的“复制诊断信息”入口，包含应用版本、浏览器类型、播放阶段、预期/实际倍速、错误码和必要耗时。
- [x] 诊断信息脱敏，诊断数据不混入正常产品文案；提交或上传由使用者明确触发。
- [x] 线上异常能够对应到具体发布版本和回归用例，避免只得到“刷新后好了”的结论。

## 三、全部产品功能清单

### F01 — 持续卡顿后的受控自救

- [x] 区分首次启动慢、持续缓冲、媒体错误、暂停、拖动和后台状态。
- [x] 使用实际播放进度判断持续卡顿，而不只依据等待事件或线路颜色。
- [x] 先进行有限恢复，再选择其他可用线路；设置次数上限、冷却和停止条件，避免循环换线。
- [x] 保留正确剧集、可靠进度、所选倍速、音量/静音和全屏状态。
- [x] 恢复失败时保留可理解的错误状态，提供重试、换线和返回入口。

验收：短暂抖动、暂停和拖动不误触发；持续无进度触发恢复；全部线路失效时停止自动尝试，后续手动重试仍有效。

### F02 — 全屏内完成常用操作

- [x] 显示片名、季/集及正在加载的目标集数。
- [x] 增加全屏选集和换线入口；沿用播放器原生底栏触发器，桌面使用浮层，窄屏按需使用可滚动面板。字幕、定时及跳过设置统一进入原生齿轮，不另设顶部操作栏。
- [x] 本轮设置候选每次打开齿轮均用原生 API 回到一级；比例直接提供4:3/16:9，选中项与实际画面一致。用户主动选过的合法值在本标签页会话内跨媒体重建继承；未选择时保留原画比例，不为默认选中而拉伸超宽视频。二级菜单保留明显的返回箭头、键盘语义和焦点路径。
- [x] 切集、换线提供即时反馈和忙碌状态；重复点击不重复推进剧集。
- [x] 失败后原地重试；返回选集面板和关闭面板保留合理焦点。
- [x] 已建立原生全屏、网页全屏及切换的连续性回归；自动引擎、实际浏览器与正式站的结果分开登记。
- [ ] 桌面 Safari 正式站的 HLS 原生全屏切集仍待独立实播。此前自动化重复点击会退出全屏，不能据此认定媒体切集退出。另已修复重建后全屏按钮状态与实际宿主不一致的问题。

验收：常用操作无需退出全屏；正确继承剧集、进度和倍速；最后一集、加载失败及键盘操作均有完整状态。

### F03 — 首页轻量续播通知

- [x] 首页只提示最近一个有有效进度的作品，仅显示片名、必要季/集、“继续”和关闭入口；不展示历史列表、海报或进度条。
- [x] 通知位于页面底部，显示三十秒后自动收起，与普通操作反馈共用通知区域；窄屏自然换行，不遮挡底部导航。
- [x] 复用原有历史与规范集号，继续时进入正确集和进度；完成上一集后仍先解析正片对应关系，不把预告当下一集。
- [x] 手动关闭或自动收起只记录本标签页会话内的通知状态，不删除收藏、观看记录和进度；返回首页或刷新不反复展示同条，也不顺次弹出更早历史。
- [x] 已看完且无下一集、缺失资料或无有效进度时不提示；有效旧记录不按记录年龄强制失去续播能力。完整历史页及其移除、清空和恢复入口保留。

验收：通知仅出现一条；三十秒收起、手动关闭、导航返回、刷新及新进度的显示规则分别验证；继续后核对实际剧集和进度；关闭前后收藏与历史原值不变。最新通知样式的浏览器和正式站验收单列于本轮门禁。

### F04 — 可信的可播状态

- [x] 区分影片资料存在、尚未核实、近期播放成功和近期失败。
- [x] 显示必要的核实时间和过期状态，不将未知或验证失败标记为没有片源。
- [x] 复用实际成功证据和缓存；限制并发、频率和流量，不在首页对全部影片与全部来源执行探测。
- [x] 找源过程提供清晰状态，失败原因与重试规则一致。

验收：网络/认证失败、真正无资源、缓存过期和部分来源成功均能正确呈现；过期结果不冒充当前保证。

### F05 — 搜索按作品、季和版本组织

- [x] 按作品、季、版本聚合结果，将同版本片源收进条目内部。
- [x] 处理别名、年份、季号、特别版及同名不同作品；不确定的结果保持独立。
- [x] 保留流式返回和精确片名优先，补充必要的类型、季和年份筛选。
- [x] 后续结果到达时避免焦点丢失和正在点击的条目跳位。

验收：多源同作品不重复堆海报，同名异作不误合并，流式更新与返回列表保持稳定。

### F06 — 跨线路正确对齐季与集

- [x] 规范作品、季、集、特别篇标识，使用集名信息建立对应关系，而不只依赖数组下标。
- [x] 覆盖缺集、预告、正片、特别篇、上下集和顺序不同的来源。
- [x] 新规范标识与旧记录保持兼容映射，既有收藏、观看历史及片头片尾配置不因标识变化而丢失。
