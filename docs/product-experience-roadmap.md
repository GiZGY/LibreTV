# OpenStream 产品体验与防回归计划

更新日期：2026-11-06

计划基线：已发布的 `origin/main` 提交 `bc1ae53`。现有全屏下一集、自动连播、片头片尾设置、倍速继承修复和新验证会话七天有效期继续保留，不作为待新增功能重复建设。

目标：打开后便于继续观看，播放中便于处理问题，异常后能够可靠恢复。全部条目纳入实施范围；产品不提供账号注册或登录。跨设备同步由使用者选择启用，以明确的设备配对授权建立关联。

状态约定：清单初始均为未完成。条目只有在实现、对应回归、浏览器验收通过且证据可追溯后才勾选；生产发布状态另外记录。计划中的测试和验收标准不代表已经执行通过。

## 一、实施顺序与依赖

| 批次 | 工作范围 | 依赖及完成出口 |
| --- | --- | --- |
| 0：防回归地基 | G01–G03，历史缺陷回归，播放状态约束 | 发布阻断检查实际接入 CI；真实媒体测试先复现历史缺陷，再验证修复 |
| 1：稳定播放 | F06 跨源集号对齐、F01 卡顿自救 | 集号与恢复预算可靠后，再扩展自动换线和全屏换线入口 |
| 2：日常高频体验 | F02 全屏完整操作、F03 首页继续观看，F14 首轮触控检查 | 两项功能分别提交、分别验收；保留已修复的倍速、进度和全屏行为 |
| 3：可信找片 | F04 可播状态、F05 搜索分组 | 使用规范作品/季/集标识；复用缓存，避免首页全量探测 |
| 4：追更 | F07 追更与收藏分类 | 更新集数来源、刷新节流、继续观看入口形成闭环 |
| 5：观看便利功能 | F08 一键记片头片尾、F09 本集不跳、F12 睡眠定时、F13 外挂字幕 | 每项独立提交；完成 F14 对相关新控件的复查 |
| 6：数据备份 | F10 导出、导入与迁移保护 | 先具备可验证的备份恢复能力，再引入跨设备写入 |
| 7：跨设备续播 | F11 无账号设备配对与可选同步 | 配对授权、同步存储、冲突规则和数据迁移形成 ADR 后实施 |

每批通过验收后单独发布，不将全部能力打成一次大改。后续工作以当时的正式主分支为基线，现有无关未提交改动保持隔离。

## 二、防回归地基：先做再扩展

### G01 — 真实媒体自动回归与状态约束

- [x] 明确播放会话、媒体实例、持久化偏好和临时操作的责任边界；沿用现有模块，渐进整理，不为此重写前端框架。
- [x] 将倍速恢复与一次性的进度恢复分离；媒体重载、错误恢复、重新播放均执行一致性检查。
- [ ] 取消已失效的请求，隔离旧实例事件；旧集的回调不修改新集的倍速、进度、线路或历史记录。
- [x] 建立本地可重复生成的 MP4/HLS 测试媒体；浏览器测试不依赖公网片源，运行时静音。
- [ ] 在 CI 中运行真实浏览器媒体回归，而不只执行源码片段、模拟视频或静态断言。
- [x] 首批覆盖 Chromium；补充 WebKit 引擎回归。Chrome/Edge 为首批实际浏览器验收对象，Safari/iOS 涉及的能力另做真机验证，不将 WebKit 模拟结果等同于真机结果。
- [ ] 覆盖手动下一集、自然结束连播、跳片尾切集、手动换线、自动换线、HLS 错误恢复、媒体重载、拖动进度、后台恢复及长按临时加速。
- [ ] 增加连续多次切集、快速重复操作、取消后重试和旧请求延迟返回的组合测试。
- [x] 校验实际媒体时间相对真实时间的增速；正常采样窗口不少于 10 秒，同时记录缓冲、拖动、暂停等干扰，异常窗口单独判定，不伪装为倍速通过。
- [x] 为新发现的缺陷增加先失败、修复后通过的测试；新代码、播放器库和依赖升级继续执行相应历史回归。

### G02 — 体验指标

- [ ] 建立点击播放到首帧的耗时基线，分别识别验证、找源、地址解析和媒体加载阶段。
- [ ] 定义卡顿占比、切集成功率、恢复成功率和用户主动换线次数。
- [ ] 成功标准包含正确剧集、媒体进度实际增长和状态继承；HTTP 200、容器健康、标签文字正确不单独作为播放成功证据。
- [ ] 先测量并固定统计口径，再制定性能阈值；记录改动前后对比，避免凭感觉宣布优化。
- [x] 指标采集遵循最小化原则，不采集 Cookie、Token、签名媒体地址或完整观看记录。

### G03 — 问题诊断

- [x] 增加主动触发的“复制诊断信息”入口，包含应用版本、浏览器类型、播放阶段、预期/实际倍速、错误码和必要耗时。
- [x] 诊断信息脱敏，诊断数据不混入正常产品文案；提交或上传由使用者明确触发。
- [x] 线上异常能够对应到具体发布版本和回归用例，避免只得到“刷新后好了”的结论。

## 三、全部产品功能清单

### F01 — 持续卡顿后的受控自救

- [ ] 区分首次启动慢、持续缓冲、媒体错误、暂停、拖动和后台状态。
- [ ] 使用实际播放进度判断持续卡顿，而不只依据等待事件或线路颜色。
- [ ] 先进行有限恢复，再选择其他可用线路；设置次数上限、冷却和停止条件，避免循环换线。
- [ ] 保留正确剧集、可靠进度、所选倍速、音量/静音和全屏状态。
- [ ] 恢复失败时保留可理解的错误状态，提供重试、换线和返回入口。

验收：短暂抖动、暂停和拖动不误触发；持续无进度触发恢复；全部线路失效时停止自动尝试，后续手动重试仍有效。

### F02 — 全屏内完成常用操作

- [ ] 显示片名、季/集及正在加载的目标集数。
- [ ] 增加全屏选集和换线入口；桌面采用侧栏/浮层，手机采用适合触控的面板。
- [ ] 切集、换线提供即时反馈和忙碌状态；重复点击不重复推进剧集。
- [ ] 失败后原地重试；返回选集面板和关闭面板保留合理焦点。
- [ ] 持续验证原生全屏、网页全屏及两者切换时的状态连续性。

验收：常用操作无需退出全屏；正确继承剧集、进度和倍速；最后一集、加载失败及键盘操作均有完整状态。

### F03 — 首页继续观看

- [ ] 首页优先展示最近观看条目、季/集、观看位置和继续入口。
- [ ] 复用现有历史数据，不建立相互矛盾的第二套进度。
- [ ] 已看完、未开始、历史缺失及原线路失效分别处理。
- [ ] 移除条目和清空操作保留现有恢复能力，不误删收藏。

验收：从首页进入正确集和正确进度；移动端信息不拥挤；新用户首页保持简洁。

### F04 — 可信的可播状态

- [ ] 区分影片资料存在、尚未核实、近期播放成功和近期失败。
- [ ] 显示必要的核实时间和过期状态，不将未知或验证失败标记为没有片源。
- [ ] 复用实际成功证据和缓存；限制并发、频率和流量，不在首页对全部影片与全部来源执行探测。
- [ ] 找源过程提供清晰状态，失败原因与重试规则一致。

验收：网络/认证失败、真正无资源、缓存过期和部分来源成功均能正确呈现；过期结果不冒充当前保证。

### F05 — 搜索按作品、季和版本组织

- [ ] 按作品、季、版本聚合结果，将同版本片源收进条目内部。
- [ ] 处理别名、年份、季号、特别版及同名不同作品；不确定的结果保持独立。
- [ ] 保留流式返回和精确片名优先，补充必要的类型、季和年份筛选。
- [ ] 后续结果到达时避免焦点丢失和正在点击的条目跳位。

验收：多源同作品不重复堆海报，同名异作不误合并，流式更新与返回列表保持稳定。

### F06 — 跨线路正确对齐季与集

- [ ] 规范作品、季、集、特别篇标识，使用集名信息建立对应关系，而不只依赖数组下标。
- [ ] 覆盖缺集、预告、正片、特别篇、上下集和顺序不同的来源。
- [ ] 新规范标识与旧记录保持兼容映射，既有收藏、观看历史及片头片尾配置不因标识变化而丢失。
- [ ] 无法可靠对应时提示该线路缺少当前集，不静默切到其他集。
- [ ] 同集不同剪辑或时长显著不同的版本明确区分，进度对齐策略单独验证。

验收：A 源为 1/2/3 集、B 源为 1/3 集时，第 2 集不误切到 B 源第 3 集。此项为已识别代码风险的预防工作，不标作已复现线上故障。

### F07 — 追更与收藏分类

- [ ] 增加“在追 / 想看 / 已看完”分类，兼容现有收藏。
- [ ] 展示已更新集数、已看集数和下一集入口，增强已有的新集提示。
- [ ] 更新查询具备刷新时间、缓存和频率限制，不对全部收藏持续轮询。
- [ ] 处理停更、完结、源失效和不同来源更新不同步的情况。

验收：新增集数提示有证据；当前进度不被更新查询覆盖；收藏分类升级不丢数据。

### F08 — 一键记录片头片尾

- [ ] 支持当前位置记作片头结束，或根据当前位置计算片尾长度。
- [ ] 沿用当前每部剧的记忆，显示实际秒数和生效范围。
- [ ] 处理刚开播、接近结尾、片头片尾重叠及短视频等边界。

验收：设置后下一集正确应用；错误范围不误跳正文，恢复默认有效。

### F09 — 本集暂不跳过

- [ ] 支持本集保留片尾，必要时也可临时保留片头。
- [ ] 临时选择与整部剧的长期设置分离，下一集按长期设置执行。
- [ ] 明确与自动连播的关系，避免临时保留片尾却仍提前切集。

验收：仅影响目标集，长期偏好保持不变，切集失败与重试不意外恢复提前跳过。

### F10 — 收藏与历史导出、导入

- [ ] 导出收藏、分类、观看进度及适合备份的偏好，使用带版本号的数据格式。
- [ ] 不导出登录态、验证 Cookie、密钥或临时签名播放地址。
- [ ] 导入前验证结构与大小，展示合并/替换影响；替换前保留恢复点。
- [ ] 覆盖重复导入、损坏文件、旧格式、部分记录缺失和恢复流程。

验收：导出后在隔离环境导入可恢复数据；失败不破坏原有记录；重复导入不产生重复收藏。

### F11 — 无账号设备配对与跨设备续播

- 产品约束：不建设账号、注册或登录功能；默认本地使用，配对和同步主动启用。
- 候选交互：一台设备生成短期、一次性的配对二维码，另一台扫码后经确认加入同一同步空间。服务端进度存储是否启用、配对和恢复的具体方案在 ADR 阶段确认。
- [ ] 以设备配对授权建立关联，每台设备独立授权且可撤销；配对码不作为永久同步凭证。
- [ ] 不使用 IP、设备指纹、共享站点口令或人机验证 Cookie 猜测同一使用者；设备关联不复制验证凭证或绕过现有访问保护。
- [ ] 明确匿名同步空间、最小化同步存储、配对确认、过期、限流和撤销机制，并形成 ADR。
- [ ] 定义多端进度冲突、离线合并、删除同步和数据版本规则。
- [ ] 同步收藏、分类、进度及明确选择的偏好，不同步临时媒体会话和验证凭证。
- [ ] 保持本地使用能力，使用者可选择启用或关闭同步。
- [ ] 定义清除浏览器数据、设备遗失、重新配对及可选恢复码的处理方式，不承诺账号式找回。
- [ ] 验证迁移、失败重试、幂等、解除配对和数据恢复。

验收：全流程无账号注册和登录；已配对设备恢复正确剧集和进度，未授权或已撤销的设备不读取同步数据；晚到的旧会话不覆盖新的观看结果；关闭同步后仍可本地使用。一次性扫码传递当前进度属于“接力观看”，与配对后的持续自动同步分别描述和验收。

### F12 — 睡眠定时

- [ ] 支持按时长停止和本集结束停止，提供剩余时间、取消和延长入口。
- [ ] 明确“本集结束停止”与跳片尾、自动连播的优先关系，停止时不进入下一集。
- [ ] 定时到期只执行一次，后台恢复、切集和播放器销毁不产生遗留计时器。

验收：定时停止后不被连播或错误恢复重新拉起，取消和延长立即生效。

### F13 — 外挂字幕

- [ ] 支持手动载入 SRT/VTT，调整字号和时间偏移。
- [ ] 支持字幕关闭、重新选择、编码错误和非法文件反馈。
- [ ] 定义选集字幕的适用范围，避免把上一集字幕自动带给下一集。
- [ ] 保证字幕文字不作为可执行页面内容，限制文件大小，默认本地处理。

验收：字幕与倍速、拖动、全屏兼容；切集不串字幕，损坏文件不影响视频播放。

### F14 — 高频控件与移动端专项

- [ ] 高频触控目标至少 44px，避免将桌面布局直接缩小为手机布局。
- [ ] 检查选集面板、线路列表、倍速弹层、字幕与定时设置的滚动、遮挡和焦点。
- [ ] 保留键盘操作、可见焦点、减少动态和现有明暗主题能力。
- [ ] 检查页面、弹层和字幕对比度，状态含义不只依赖颜色。
- [ ] 所有新增页面覆盖空、加载、部分成功、失败、不可用和成功状态。
- [ ] 用户可见文字保持自然产品文案，不展示内部字段、调试信息或制作说明。

验收：桌面和窄屏分别完成浏览器检查，触控行为补充实际设备验证。此项贯穿各批次，不留到全部功能完成后才检查。

## 四、历史缺陷的永久回归清单

| 编号 | 历史问题或约束 | 发布必须保住的结果 |
| --- | --- | --- |
| R01 | 实际倍速回到 1×，界面仍显示所选倍速 | 普通播放时选择值、实际值、默认值和界面一致；临时加速时实际值与界面一致，保存值不被污染；恢复和切集后继续成立 |
| R02 | 全屏切集需退出，或媒体重建破坏全屏 | 手动、自然结束、跳片尾切集及换线都覆盖原生/网页全屏，不只测手动下一集 |
| R03 | 验证加载/配置失败、Cookie 未生效或身份不一致 | 未验证时保护仍有效；失败原地重试；确认会话真正生效后再继续请求，真实浏览器身份保持一致 |
| R04 | 验证频率与持久化 | 新会话固定七天有效，覆盖刷新、关闭重开、换网络、到期及篡改；旧凭证按兼容规则处理，不把临时测试会话差异误判为生产故障 |
| R05 | 来源查询失败与负缓存 | 区分认证/网络失败与真实无资源；恢复不抹掉收藏、历史和偏好；历史负缓存修复具备一次性与幂等验证 |
| R06 | 播放会话与数据保护 | 旧集回调不污染新集历史；重试不重复推进剧集，长期设置与临时选择相互隔离 |

R01–R05 的现有修复和测试继续保留并扩展。R06 是所有后续功能的共同约束，不代表新增已复现故障。

## 五、每项工作完成与每次发布的门槛

- [ ] 改动范围单一，沿用项目分支约定，不夹带无关代码、用户数据或本地配置。
- [ ] 对应新增测试及相关历史回归通过，失败、取消、重复操作和恢复路径有覆盖。
- [ ] 涉及播放器时执行真实媒体浏览器测试，检查实际进度，不以截图或标签代替。
- [ ] 改动前记录基线，候选版本完成桌面与移动端的相关布局和交互验收。
- [ ] CI 为实际执行成功，跳过或未运行的检查不记作通过；检查失败时阻断发布。
- [ ] 历史回归预期变更单独说明并审查，不通过删除、跳过用例或削弱断言来取得绿色检查。
- [ ] 预览验收通过后发布，记录提交、部署版本与回滚点；共享数据库/存储改动另行核对备份与恢复。
- [ ] 正式站点确认版本生效，复查关键路径；播放器发布至少复查手动下一集、自然结束连播和跳片尾切集。
- [ ] 生产验收失败时按回滚方案恢复，当前批次重新打开，不继续叠加下一批功能。
