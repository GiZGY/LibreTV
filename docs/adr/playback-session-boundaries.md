# 播放状态与诊断边界

状态：采用，2026-11-06。

## 决策

- `LivePlayback` 拥有当前影片、集数、线路与持久进度；只有当前媒体对象可以写入。失效请求通过取消信号和代次检查退出。
- 播放器实例拥有媒体事件、一次性进度恢复和临时按键加速。实例销毁时解除事件和计时器；旧实例事件不得更新新集。
- 持久偏好保存所选倍速；临时加速只改变当前有效值。媒体生命周期持续对齐 `playbackRate` 与 `defaultPlaybackRate`，不依赖一次性进度恢复。
- 脱敏诊断独立于观看记录，只在内存保留最多 20 次会话。诊断不包含片名、影片标识、媒体地址、Cookie、凭据或完整浏览器身份。
- “复制诊断信息”是唯一提交入口；默认没有网络上传。版本来自当前内容哈希。

## 统计口径

播放意图被接纳时建立一次尝试：继续观看、选集、换线和重试在状态变更前记录起点；自然结束或跳片尾在通过推进条件后、保存旧集进度前记录起点。直接打开播放地址时以播放路由入口为起点。解析失败仍保留尝试；被新操作取代或导航取消的尝试单独标为已取消。

起点至首个实际视频帧分为互不重叠的页面准备、访问验证、找源、地址解析、播放器/HLS 引擎加载、媒体就绪六段。首帧取实际视频帧回调；没有帧回调时使用非暂停、非拖动、非后台的实际进度增长。六段之和与首帧总耗时使用同一时钟，不将“取得地址”当作首帧。

切换成功需要当前媒体对象、预期规范集号一致，以及至少两秒连续普通播放的实测媒体时间斜率与所选倍速一致，同时验证实际速率和默认速率。集号与媒体对象只在内存比较，不输出到诊断。临时长按加速的有效倍速与长期所选值区分；临时加速不会制造普通倍速成功，也不会被误记为失败。成功状态记录本次尝试曾经满足的条件，当前速率是否仍一致另由 `rateVerified` 表示。

切换成功率的分母为已成功与已失败的转场尝试；尚在等待和主动取消分别计数，不混作网络故障。恢复调用和新线路恢复都计入恢复尝试，只有身份和实速恢复后才计成功。统计只保留当前及最近最多二十次尝试；分位数只描述本机这一小段观察，不代表全站统计。

卡顿占比为可观察等待时间除以播放与等待时间之和。暂停、拖动、结束、失败、页面隐藏会结束当前等待及速率窗口；页面重新可见后重新取样。长时间无事件的间隔不被推算成正常播放时长。诊断中的实际倍速短窗用于判断一致性，不替代发布门禁的十秒媒体实速验收。

真实倍速回归采样至少 10 秒，并同时断言无等待干扰、实际速率、默认速率及显示值。历史修复前提交的媒体重载测试应失败；发布候选必须通过。Chromium 与 WebKit 回归不等同于 iOS 真机验收。

## 恢复与发布

真实媒体由本地 FFmpeg 生成，不依赖公网来源；运行时静音。浏览器回归使用独立 HTTP 服务，并在退出后清理测试媒体。构建、兼容性检查与浏览器测试顺序执行，避免旧 UI 的构建产物覆盖正在验收的新 UI。

本批不修改数据库。回退采用上一正式部署及对应 Git 提交；观看记录和长期偏好仍兼容上一版。
