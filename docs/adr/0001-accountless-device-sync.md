# ADR-0001：可撤销的无账号设备同步

日期：2026-11-06 · 状态：实施

## 决策

产品保持无账号、无注册、无登录。默认只在本地保存；“设备同步”由使用者主动启用。匿名空间、设备凭据和站点访问验证相互独立；不使用 IP、指纹、共享访问口令或人机验证 Cookie 关联设备。

复用目录数据库连接，但所有新表都位于 `openstream_sync` 私有 schema。迁移只创建该 schema，不修改目录表；PUBLIC 不具备 schema/table 权限。生产运行角色只需此 schema 的表权限。上线先核对数据库恢复点，执行幂等迁移，再启用 `DEVICE_SYNC_ENABLED=1`。关闭开关即可停止远端读写，旧前端和本地观看仍可使用。回退不删除同步数据，不执行 DROP。

## 授权流程

首台设备持有随机 256 bit bearer 凭据；服务端只保存 SHA-256 摘要。每台后续设备分别授权，凭据不共享，设备可单独撤销。配对邀请有效五分钟，随机秘密只在 URL fragment 或本机输入框中出现，不写入访问路径、分析日志或第三方二维码服务。二维码完全在本地生成。

新设备扫描/粘贴邀请后处于待确认状态，不能读数据。两台设备展示相同的六位核对码，原设备确认设备名称和核对码后才批准。邀请一次只接纳一台设备；取消、批准和到期后不可再用。加入请求含幂等设备凭据，网络重试不会创建重复设备。站点的人机验证仍独立执行。

每空间最多十台设备、两张待用邀请；数据库持久限流不以 IP 充当身份。无凭据的创建/加入/恢复另有全局预算，已授权操作按设备限流；平台 WAF 可再限制滥用，但不是关联依据。

## 数据与冲突

仅同步收藏分类、最小作品资料、剧集/位置/时长和观看时间、片头片尾设置。播放偏好只有主动选择后才同步。不得上传媒体地址、Cookie、密钥、搜索记录、临时字幕或定时器。每条记录独立版本，删除产生墓碑；完整快照有大小/数量限制，避免游标与并发提交次序导致丢失。

更新采用记录版本 CAS。晚到的离线修改不得静默覆盖远端新值；冲突必须明确选择“保留此设备”或“使用同步记录”。观看会话先以当前版本申请独占 session，后续进度含单调序号。新会话成功申请后，旧会话即使延迟回调也不可写入。离线会话只能用原基线申请；若基线已改变则进入冲突处理，不自动重试覆盖。服务端时间决定版本，不依赖设备时钟判断先后。

请求含随机操作 UUID，成功写入后的重试按内容与版本识别。不同内容重用同一请求 ID 被拒绝。各条记录写入为原子 CAS；部分成功会明确返回，不假装整个批次成功。客户端串行同步、失败保留本地队列，后台不持续轮询；有修改时防抖；播放中只有本地进度变化才触发合并同步，最多每 30 秒一次；暂停、切页、回到前台、重新联网时立即补同步。静止页面不做周期拉取，因此另一端的变化在这些事件或“立即同步”发生时获取，不承诺静止页面实时推送。

## 退出、遗失与恢复

关闭自动同步不删除本地收藏和进度，也不撤销其他设备。解除本设备授权会撤销其凭据；其他设备仍可用。单独撤销某台设备会同时取消该设备发出的未完成邀请。删除同步空间需二次确认，远端所有凭据立即失效；本地数据保留。

启用时在当前浏览器会话提供随机恢复码，可另存到离线位置。恢复码只以摘要入库，不自动放入普通数据备份。恢复操作撤销所有旧设备、取消邀请、轮换恢复码并签发新的设备凭据。恢复码也遗失且无其他已授权设备时，只能重新建立空间和导入本地备份，不承诺账号式找回。

## 验证

使用 PGlite 运行真实 SQL，覆盖迁移幂等、目录数据不变、未批准访问、配对到期/重复/取消、确认、单设备撤销、恢复旋转、版本/序号冲突、旧会话隔离、删除墓碑、失败重试和大小上限。前端通过两个隔离浏览器上下文完成授权和跨设备数据往返；不将单浏览器 localStorage 测试当跨设备成功。

## 存储边界与运维

每个空间最多 500 部仍有收藏/进度/跳过设置的作品，三类记录共用作品配额。全部移除某作品后释放作品配额；删除墓碑仍保留在每空间 2,000 行上限内，防止离线旧记录复活。作品/记录采用受 CHECK 和 UNIQUE 约束的 slot，跨请求并发不会突破数量限制，也不会让失败的插入消耗名额。设备十个 slot 和邀请两个 slot 同样由数据库约束。

同步服务全局最多 2,000 个空间、20,000 条数据记录，JSON 数据加每记录 512 byte 预留最多 20 MiB；插入/更新在同一 SQL 语句内核算预算，超限会回滚整条操作，不返回假成功。新建/增长写入还只读检查整库 350 MiB 和同步 schema 实际 32 MiB 软上限，检查最多缓存 30 秒，为索引与凭据保留余量。满额后本地数据仍保留，远端读取、撤销和删除空间不依赖增长预算；减少数据的墓碑写入仍允许执行。限额不影响目录表，也不清除目录内容。

新增写入机会式检查一个数据库级五分钟清理门闩。每轮分别清理最多 200 条七天前操作回执、过期一天配对、过期一天限流窗口，以及无配对引用的一天前待确认设备；过期字段有索引。不新增高频 cron，手动 `node scripts/device-sync.mjs prune` 可在运维窗口执行完整过期清理。迁移使用 Neon 单次原生事务，任一 DDL 失败会全量回滚；重复执行不更改目录表。

客户端在首次授权、加入、发出邀请和每次变更发送之前，先持久化不可变操作和随机凭据；保存失败时不发请求。网络失败、服务端异常、截断 JSON 和刷新均复用同一操作，后续进度排队而不替换正在确认的操作 ID。明确无效的恢复码可以重新输入；不确定的结果继续保留待重试状态。远端无变化时不重建页面；本机数据损坏或超出 500 部作品时停止同步但保留设备管理和本机修复入口。

## 2026-11-06：事件同步与本地资料保留

- 删除全局 30 秒网络轮询；本地变更合并、焦点/可见性恢复、导航、联网与显式同步是触发源。相邻事件合并成一次任务，已安排的较早任务不被后续进度持续推迟。
- 配对握手仍在可见且打开的配对窗口内以 2.5 秒检查状态，完成、过期、关闭或隐藏即停止。这是有明确生命周期的短期等待，不是全站后台轮询。服务端仍使用已有请求接口，不引入常驻 WebSocket/SSE 服务。
- 同步仅携带最小作品标识。接收远端进度时不删除本机海报及片源资料，存储恢复也保留这些资料；导出和远端同步继续使用脱敏后的独立数据契约。
- 远端记录变化不重建探索列表或首页轮播；收藏状态就地更新，首页续播提示按已有通知生命周期刷新。
